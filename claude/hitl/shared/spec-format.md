# Spec format (hitl 0.13)

Adapted from Fission-AI/OpenSpec (MIT) — see NOTICE.md. Source: docs/writing-specs.md, docs/concepts.md @ 6d04a1b.
Changes: stable ids are the identity (no RENAMED), Rules/Flows/Terms kinds, Retired IDs tombstones, Change History.

The parser is `scripts/lib/specmd.mjs`; the ids and regexes are in `scripts/lib/specids.mjs` (normative). Check any file
with `hitl-index spec validate [<change-id>] --json`. Templates: `shared/templates/{proposal,spec,spec-delta,glossary,design,data-model}.md`,
`shared/templates/contracts/{openapi.yaml,asyncapi.yaml,schema.json,cli.md}`.

## Standards (0.6.1) — templates, examples and sources in `shared/formats/`
| artifact | standard | lint codes (all warnings) |
|---|---|---|
| requirement statement | ISO/IEC/IEEE 29148:2018 · INCOSE GtWR v4 · EARS | `REQ_VAGUE` `REQ_COMPOUND` `REQ_PASSIVE_NO_ACTOR` |
| NFR (`Quality:` + `Fit:`) | ISO/IEC 25010:2023 · Volere fit criterion | `NFR_NO_FIT` |
| decision table in a Rule | OMG DMN 1.6 hit policies | `DT_NO_HIT_POLICY` `DT_HIT_POLICY` `DT_COLUMNS` `DT_ROW_CELLS` `DT_NO_RULES` `DT_OVERLAP` |
| lifecycle (Rule, or design `## State machines`) | Mermaid `stateDiagram-v2` + transition table | `SM_COLUMNS` `SM_NONDETERMINISTIC` `SM_UNREACHABLE` `SM_DIAGRAM_MISMATCH` `SM_MERMAID` |
| use case (Flow) | Cockburn fully dressed (lite) | `UC_NO_ACTOR` `UC_NO_STEPS` `UC_EXT_REF` `UC_NO_GUARANTEE` |
| decision <KEY>-D<n> | Nygard ADR · MADR 4.0.0 | `DESIGN_DEC_SUPERSEDE_UNKNOWN` `DESIGN_DEC_DETAIL_UNKNOWN` `DESIGN_DEC_INCOMPLETE` |
| contracts | OpenAPI 3.1.1 (3.2) · AsyncAPI 3.0 · JSON Schema 2020-12 · CLI md | `CONTRACT_PARSE` `CONTRACT_VERSION` `CONTRACT_STRUCTURE` |
| architecture (optional) | C4 Context/Container via Mermaid | — |
Requirement-quality lints run on a change's ADDED/MODIFIED blocks only; `spec.qualityLint: "off"` silences them,
`spec.vagueTerms` / `spec.vagueTermsExtra` configure the vague-term list (EN + VI built in).

## Layout
```
.hitl/specs/<capability>/spec.md      living spec (b) — written only by `hitl-index spec merge|archive`
.hitl/specs/GLOSSARY.md               living glossary (b) — same
.hitl/changes/<change-id>/            active change
  proposal.md (b) · specs/<capability>/spec.md (b, delta) · glossary.md (b, delta)
  design.md (a) · data-model.md (a) · contracts/* (a) · tasks.md (a) · .base.json (generated)
.hitl/archive/<YYYY-MM-DD>-<change-id>/   archived change (frozen)
```
(b) business-readable: no code names, file paths, class/function/library names, SQL or HTTP verbs (`BIZ_CODE_TOKEN`).
(a) developer/agent only. Every file starts with `<!-- audience: business -->` or `<!-- audience: dev -->`.

## Names and ids (0.13)
| thing | rule | example |
|---|---|---|
| change id | `(feat\|fix\|refactor\|perf\|docs\|test\|chore)-<slug>`, ≤ 48 chars, unique forever | `feat-password-reset` |
| change key | 2–5 upper-case letters in the proposal meta `\| key: PWR`, unique forever (active + archived changes, legacy keys, quick-file keys, reserved `QT`) | `PWR` |
| capability | lower-case words joined by `-`, flat, a business area; it is the folder, not part of any id | `accounts` |
| requirement / scenario | `<KEY>-R<n>` / `<KEY>-R<n>.S<k>` | `PWR-R1`, `PWR-R1.S2` |
| rule / flow | `<KEY>-BR<n>` / `<KEY>-UC<n>` | `PWR-BR1`, `PWR-UC1` |
| decision (design.md) | `<KEY>-D<n>` | `PWR-D1` |
| task / acceptance criterion | `<KEY>-T<n>` / `<KEY>-T<n>.AC<k>` | `PWR-T3`, `PWR-T3.AC2` |
| quick-file key (0.13.2) | each `.hitl/tasks/quick-<slug>.md` has its own key in its header `← Change: none \| key: QFLKM`: `Q` + the first letter of the slug + 3 hash letters, 5 in all (`hitl-index next-id --quick <slug>`); its task is `<KEY>-T1`. The shared `QT` (`QT-T7`, 0.13.0–0.13.1) is legacy: `/hitl:migrate` | `QFLKM`, `QFLKM-T1.AC1` |
| glossary term, note, finding | local: the term (case-folded), `N-k`, `F-n` | `Reset link`, `N-2`, `F-1` |

- `<KEY>` is the key of the change that **created** the id. ADDED blocks use the change's own key
  (`DELTA_KEY_MISMATCH`); MODIFIED/REMOVED keep the original id; a living requirement keeps its id forever, and new
  scenarios of a MODIFIED requirement continue its `S` numbers.
- Numbers are max+1 within the key and never reused. Allocate with `hitl-index spec next-id <change-id> [--kind R|BR|UC|D]
  [--count n]` and `hitl-index spec next-id --scenario <REQ-ID>`.
- Key codes: `CHANGE_KEY_MISSING`, `CHANGE_KEY_BAD`, `CHANGE_KEY_TAKEN`. Suggest a free key with
  `hitl-index spec key <change-id> --title "…"`; check one with `hitl-index spec key --check <KEY>`.
- Ids of unknown origin found by `/hitl:migrate` (written before hitl) get a legacy key per capability: `L` + the old
  capability key, ≤ 5 letters (`LACC-R1`).
- Pre-0.13 ids (`T-n`, `D-n`, capability keys in spec meta, `hitl.lock/1`) → `IDS_LEGACY`: run `/hitl:migrate`.
- A removed id goes to `## Retired IDs` and is never reused.

## Living spec
```markdown
<!-- audience: business · generated by hitl-index spec merge — edit through a change, not by hand -->
# Accounts
> capability: accounts | updated: 2026-11-02

## Purpose
## Requirements
### Requirement: PWR-R1 Reset password by email
When a registered user asks to reset their password, the system SHALL send a single-use reset link.
Quality: security (confidentiality)   (optional ISO 25010:2023 characteristic [+ sub-characteristic] → an NFR)
Fit: no stored reset link is reusable (NFR: measurable fit criterion; shared/formats/requirement-quality.md)
Rules: PWR-BR1                   (optional)

#### Scenario: PWR-R1.S1 Known email receives a link
- GIVEN …
- WHEN …
- THEN …
- AND …
## Rules
### Rule: PWR-BR1 Reset link validity        (text, optional DMN decision table or lifecycle)
## Flows
### Flow: SGN-UC1 Recover access              (Cockburn lite: Primary actor, Success guarantee, numbered steps, extensions)
## Retired IDs
- SGN-R2 Remember me — removed by feat-2fa (2026-10-20): replaced by 2FA
## Change History
- 2026-11-02 feat-password-reset: +PWR-R1 ~SGN-R1 -SGN-R2
```
- Only these `##` sections are allowed in a living spec (`SPEC_UNKNOWN_SECTION`).
- A block runs from `### Requirement|Rule|Flow: <ID> <title>` to the next `###` or `##`.
- Requirement statement: the prose before the first `####`. One RFC 2119 keyword sets the priority:
  `SHALL`/`MUST` → must, `SHOULD` → should, `MAY` → could (`REQ_NO_KEYWORD`, `REQ_MULTI_KEYWORD`, `REQ_TOO_LONG` > 500).
- Scenario: `#### Scenario: <REQ-ID>.S<k> <title>` + bullets `- GIVEN|WHEN|THEN|AND|BUT <text>`; at least one WHEN and
  one THEN (`SCN_NO_WHEN_THEN`). A delta requirement needs ≥ 1 scenario (`REQ_NO_SCENARIO`).
- Keywords stay English; prose may be any language.

## Delta (`changes/<id>/specs/<capability>/spec.md`)
```markdown
<!-- audience: business -->
# Delta: Accounts
> capability: accounts | change: feat-password-reset
## Purpose                 (only for a new capability; then only ADDED sections are allowed)
## ADDED Requirements      (full blocks)
## MODIFIED Requirements   (FULL new block incl. unchanged scenarios + one line "Changed: …")
## REMOVED Requirements    (header + "Reason: …")
## ADDED|MODIFIED|REMOVED Rules
## ADDED|MODIFIED|REMOVED Flows
```
- Empty sections are omitted. `RENAMED` is not supported (`DELTA_RENAMED_UNSUPPORTED`).
- Two active changes that both create the same not-yet-living capability → `CAP_DUP_NEW` (warn, in `spec validate`
  and in `spec conflicts --json` `warnings[]`; exit code unchanged): archive one, then turn the other into `modified`.
- The same id in two sections → `DELTA_CONFLICT`. MODIFIED/REMOVED of a non-living id → `DELTA_TARGET_MISSING`.
  ADDED of a living or retired id → `DELTA_ID_TAKEN` (`spec archive --renumber` re-allocates it inside the change folder).
- Glossary delta `changes/<id>/glossary.md`: `## ADDED|MODIFIED|REMOVED Terms` with `### Term: <term>` blocks.

## Proposal (`changes/<id>/proposal.md`)
Meta `> change: <id> | key: <KEY> | status: draft|approved | created: … | updated: …` plus an optional `| before: <change>[, <change>]`
(0.12, written by `/hitl:plan … --before`): display only — the changes that wait for this one hold a note with
`source: <this change>`, and only those notes block (`shared/other-changes.md`). Required sections: `## Why`, `## What changes`,
`## Capabilities` (table `capability | change | requirements`; change `new|modified|retired`; or the line
"none (no behaviour change)" for docs/chore/refactor/test/perf), `## Artifacts` (`artifact | decision | why`).
Optional: Unchanged behaviour, Success criteria, Out of scope, Assumptions, Coverage, Deferred, Open questions.
`[NEEDS CLARIFICATION: …]` is a warning while draft and an error once approved.
Plan stop rule (`/hitl:plan`, `shared/interview.md` §9): `REQ_UNCLEAR` — a SHALL/MUST requirement block still holds
`[NEEDS CLARIFICATION`; `COVERAGE_GAP` — a `## Coverage` row (`| category | status | note |`) is ⚠️, ❌, unmarked, or
`—` without a reason. Both warn while draft and are errors once approved, unless `## Open questions` has a
`💡 Forced: …` line (then REQ_UNCLEAR and NEEDS_CLARIFICATION warn and COVERAGE_GAP is info).

## Design (`changes/<id>/design.md`)
Meta `> change: <id> | status: draft|approved`. `## Decisions` table (the log)
`id | decision | why | alternatives | cost if wrong | serves | status`; `serves` ids must be in the change's spec view
(`DESIGN_SERVES_UNKNOWN`); status `proposed|accepted|rejected|deprecated|superseded by <KEY>-D<n>` (`DESIGN_DEC_STATUS`).
Optional MADR records `### <KEY>-D<n> <title>` after the table (`shared/formats/decisions.md`); tables inside them are not
D rows. Optional `## Architecture (C4)` and `## State machines` sections. `## Contracts` lists
`- contracts/<file> — <boundary>` (`CONTRACT_MISSING`, `CONTRACT_UNLISTED`); contract files get a structural check
(`shared/formats/contracts.md`). Module level only: no function signatures.

## Merge and archive
`hitl-index spec merge <id>` applies REMOVED → MODIFIED → ADDED per kind (Requirements, Rules, Flows), then Terms, to the
living files, appends a `## Change History` line and records tombstones. A re-run is a no-op (`alreadyApplied`).
`hitl-index spec archive <id>` = validate + all tasks done (or `--force`) + merge + move to
`.hitl/archive/<YYYY-MM-DD>-<id>/`. Any conflict or failed precondition writes nothing.
`.base.json` holds the hash of each living block a change modifies/removes (written by `spec validate`);
a later living edit gives `BASE_CHANGED` until the delta is updated or `--accept-base <ID>` is passed.
